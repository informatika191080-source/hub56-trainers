# HUB 56 — технічний план (етап 2)

## Мета
Постійні облікові записи учнів 5–9 класів, інтерактивні вебаркуші, збереження відповідей, кабінет учителя та аналіз результатів. Використання в укритті з мобільних пристроїв.

## Компоненти
- GitHub Pages — тільки публічна оболонка та відкритий навчальний контент.
- Firebase Authentication — авторизація, ролі не визначаються довірою до браузера.
- Cloud Firestore — захищене збереження відповідей і метаданих занять; оновлення в реальному часі.
- Довірений серверний механізм — перевірка оцінок/ключів відповідей і керування ролями; не покладатися на результати, передані клієнтом.
- Локальне кешування — лише після окремого проєктування та тестування; спільні пристрої вимагають особливої обережності.

## Правила проєктування
1. Створення учнівських записів — тільки через погоджений адміністративний процес.
2. Учень бачить лише власні роботи; учитель — лише призначені класи та заняття.
3. Правильні відповіді для контрольних завдань не оприлюднюються в браузері до завершення перевірки.
4. Кожна відповідь має ідентифікатор заняття, завдання та автора; зберігається факт синхронізації.
5. Оцінювання має конфігуровану шкалу, пояснення та право вчителя на перегляд.
6. Перед тестуванням на справжніх даних — погодити політику оброблення персональних даних закладом освіти.
7. Ніяких справжніх імен учнів, паролів, ключів адміністратора у публічному GitHub.

## План першої реалізації
1. Створити окремий Firebase-проєкт HUB 56 (без реальних користувачів).
2. Увімкнути Authentication, обрати підтримуваний метод входу.
3. Підготувати базу Firestore із безпечними початковими правилами deny-all.
4. Створити тестовий учительський обліковий запис без приватних даних учнів.
5. Реалізувати вхід і перевірити розмежування прав на тестових профілях.
6. Створити один вебаркуш та моніторинг тестових результатів.
7. Перевірити захист і роботу при розривах зв'язку перед розгортанням для реальних учнів.
